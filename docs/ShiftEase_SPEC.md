# ShiftEase 仕様書

> 更新日: 2026-08-14  
> 本書は、これまでのチャット・既存デモ・現在のバックエンド実装方針を統合した仕様書。  
> **「現在すでに動いているもの」だけではなく、これまでに希望した完成形を基準**に整理する。

## 1. プロダクト概要

### 1.1 名称
**ShiftEase**

### 1.2 目的
アルバイト・店舗のシフト管理について、以下をできるだけ自動化・簡略化する。

- 従業員からのシフト希望回収
- 未提出者への催促
- 必要人数・勤務条件を考慮したシフト案作成
- 店長による確認・微調整・確定
- 確定シフトの共有
- シフト交代募集・立候補・承認
- 欠勤・遅刻の記録
- 店舗からのお知らせ・通知

コンセプトは、**「希望回収からシフト作成・共有まで。考える手間を減らす、シンプルなシフト管理」**。

---

## 2. 利用者区分

### 2.1 従業員
- 従業員番号でログイン
- 自分の希望提出・修正
- 確定シフト確認
- 他メンバーの確定シフト確認
- シフト交代募集
- 他人の交代募集への立候補
- 欠勤・遅刻記録
- 店舗からのお知らせ確認
- 通知確認

### 2.2 管理者 / 店長
- 管理者PIN等でログイン
- 店舗全体の状況確認
- 希望提出状況確認
- 必要人数設定
- 従業員情報・配置条件管理
- おすすめシフト自動作成
- シフト手動編集
- シフト確定・公開
- 交代申請の承認 / 却下
- 欠勤・遅刻記録確認
- 店舗からのお知らせ投稿

# 3. 従業員側

## 3.1 ホーム

ホームで最低限以下を確認できる。

- 氏名
- 次の確定シフト
- 希望提出状況
- 今日の出勤メンバー
- 今日の勤務タイムライン
- 店舗からのお知らせ
- 通知
- 希望提出への導線
- シフト確認への導線
- シフト交代への導線
- 欠勤・遅刻連絡への導線

### UI方針
スマホを主利用端末として想定する。下部ナビゲーションは原則4項目。

1. ホーム
2. 希望提出
3. シフト
4. 交代

## 3.2 シフト希望提出

### 対象期間
店長が指定した提出対象期間を表示する。例：8月16日〜31日分 / 締切 8月20日。

### カレンダー入力
月 / 半月単位のカレンダーから日付を選択し、勤務希望 / 勤務不可 / 未入力を視覚的に区別する。

### 1日ごとの入力
- 「入りたい」
- 「勤務不可」
- 開始時刻
- 終了時刻
- 一言メモ（任意）

### 時間プリセット
- 8:00〜15:00
- 10:00〜15:00
- 15:00〜21:00
- 17:00〜21:00

### いつもの希望
従業員ごとに通常の希望パターンを保持し、**「いつもの希望を適用」**で期間全体へ反映できる。例：月・水・金 / 10:00〜15:00。

### 保存と提出
「1日を保存」と「期間全体を提出」は区別する。
- 日ごとの編集内容を保存
- 最後に期間全体を「この内容で提出する」
- 締切までは何度でも修正可能
- 管理者には最終更新日時も表示

## 3.3 確定シフト

**確定済みのシフトのみ**従業員へ表示する。表示モードは一覧 / タイムライン。タイムラインでは、1日の時間軸上に各従業員の勤務時間をバーで表示する。

表示情報：日付、従業員名、開始〜終了、現在勤務中か / 後から出勤か、必要人数（必要に応じて表示）。

## 3.4 シフト交代

**募集する側と代わる側を別ページにはせず、「シフト交代」1ページにまとめる。**

### A. 自分のシフトを交代募集する
自分の確定済みシフト一覧から対象を選択し、理由 / メッセージ（任意）を付けて募集する。

### B. 募集中のシフトに立候補する
他従業員が募集しているシフトを一覧表示し、条件を満たす場合に **「🙋 代われます！」** を押せる。

立候補前に、既存シフト重複、勤務不可、連勤条件をチェックする。

交代フロー：募集 → 立候補 → 管理者承認待ち → 承認 / 却下 → 承認時に確定シフト更新 → 関係者通知。

## 3.5 欠勤・遅刻

当日の欠勤・遅刻はアプリだけで完結させず、**「当日の欠勤・遅刻は、まず店舗へ電話してください。この画面は記録を残すためのものです。」** と明記する。

入力：遅刻 / 欠勤、到着予定時刻またはメッセージ。送信後は管理者の「要対応」に表示する。

## 3.6 店舗からのお知らせ
ホームで店舗のお知らせを表示し、各投稿に **「確認しました」** を設置する。将来的には管理者が誰まで確認したか確認できる。

## 3.7 通知
- 明日はシフトです
- シフトが確定しました
- 条件を満たす交代募集があります
- 交代に立候補されました
- 交代が承認 / 却下されました
- 希望提出期限が近づいています
- 店舗から新しいお知らせがあります

# 4. 管理者側

## 4.1 ダッシュボード
コンセプト：**「今日やること / 要対応だけ見れば状況が分かる」**。

表示指標：今日の出勤人数、現在勤務中の人数、要対応件数、希望提出人数 / 全従業員数、次回シフトの人員不足枠数。

要対応例：遅刻、欠勤、交代承認待ち、人員不足、シフト作成上の警告。

## 4.2 希望提出状況
従業員ごとに氏名、提出状態、いつもの希望、最終更新日時、自動催促状況を表示。

### 自動催促
未提出者に対してシステムが自動通知する。例：締切3日前、締切当日、必要に応じて再通知。店長が一人ずつ連絡しなくても済む設計にする。

## 4.3 従業員管理
基本情報：従業員番号、氏名、雇用区分、通常の希望勤務パターン。

配置条件 / スキル例：一般、厨房ベテラン、全体を見られる人。

配置優先度例：通常、できれば配置、必ず1人。これらの内部情報は従業員側には原則表示しない。

## 4.4 必要人数設定
日付・時間帯ごとに必要人数を設定する。将来的には曜日・時間帯テンプレートも検討する。

## 4.5 おすすめシフト自動作成
対象期間を指定し **「✨ おすすめ案を自動作成」** でシフト案を生成する。

### ハード条件
- 勤務不可日は入れない
- 同一時間帯の重複勤務を作らない
- 店舗営業時間外に入れない
- 必要な資格 / 役割等がある場合は満たす

### ソフト条件
- 従業員の勤務希望
- 必要人数
- 勤務時間・回数の公平性
- 連勤数
- 配置優先度
- 「この時間帯にはこの役割の人を1人以上」等

### 連勤
**5連勤以上になる場合は警告**し、店長が「このままでOK / 修正する」を選べる。

### 人員不足
必要人数を満たせない時間帯は明確に警告する。

### 自動作成結果
希望どおり度、人員不足数、要確認件数、各従業員の配置案を表示。

## 4.6 シフト手動編集
半月表示 / 日別詳細表示、従業員×日付表、シフトカードのドラッグ編集、時刻変更、人の入れ替え、追加 / 削除。警告をリアルタイム再計算する。

## 4.7 シフト確定・公開
管理者が内容確認後 **「確定・公開」**。公開時に確定状態、従業員側表示、全従業員通知。確定前の案は従業員側には表示しない。印刷 / PDFにも最終対応する。

## 4.8 交代承認
元の勤務者、立候補者、日時、重複勤務、勤務不可衝突、連勤影響を確認し、承認 / 却下。承認後は確定シフトを自動更新する。

## 4.9 店舗からのお知らせ
管理者がタイトル / 本文を投稿し、従業員側には「確認しました」ボタン付きで表示。

# 5. シフト作成ルール

| 条件 | 扱い |
|---|---|
| 勤務不可 | 原則配置禁止 |
| 希望時間 | 優先して配置 |
| 必要人数 | 可能な限り満たす。不足時警告 |
| シフト重複 | 禁止 |
| 5連勤以上 | 警告 |
| 配置優先度 | 自動作成時に考慮 |
| 必須役割 | 指定時間帯に最低人数を確保 |
| 公平性 | 勤務回数・時間が偏りすぎないよう考慮 |

# 7. UI / レスポンシブ要件

## スマホ最優先
特にiPhone Safariで破綻しないこと。
- 横スクロールを原則発生させない
- input / select / textarea / card が画面幅から飛び出さない
- 長い文字列も折り返す
- safe-areaを考慮
- タップ領域を十分確保
- 下部ナビゲーションを使いやすくする

従業員画面はスマホで4項目の下部固定ナビを基本形。管理者画面はPCではサイドバー＋広い管理画面、スマホではモバイル向けナビに変形する。

# 11. 開発上の原則

- デモ用架空データと本番データを混同しない。
- 新機能追加時に既存機能を消さない。
- 可能なものはDBへ永続化する。
- スマホ表示を毎回確認する。
- 似た機能の名称はユーザーが迷わないよう明確にする。
- 自動作成は **案を作る → 店長が確認・修正 → 確定・公開** の順。
- 人員不足や5連勤などは警告として店長へ提示する。
- 店長が毎回人に催促・確認しなくてよい部分を優先して自動化する。
